# NetSteps

[Webアプリ](https://vamanashi.github.io/netsteps/) · [出典・利用について](https://vamanashi.github.io/netsteps/#sources)

IPA午後問題をゴールに、必要な知識・条件の判断・答案の組立てを小さな練習で学ぶWebサイトです。
PCでは章をコンパクトなリストで表示し、レッスンの目次と本文を分けます。
スマートフォンにも対応しますが、iPhone風の外枠はありません。

## 開発・確認

Node.js 22.12以上を使用します。

```sh
npm ci
npm run dev
npm run typecheck
npm run validate
npm run build
npm run preview
```

開発URLはViteの出力を確認してください（通常 http://localhost:5173）。
文章検証には、メール章の長い正式名称に関する既存警告が1件あります。

## 学習と進捗

- 学習一覧：21の基礎章。過去問は章の行から展開できます。
- 過去問対応表：年度・区分・問番号、主テーマ・関連テーマ、教材形式、練習実施、原問の解答、自己採点を一覧表示します。
- 進捗：実施ステップ、初回／直近の練習正解率、章別進捗、原問の解答済み件数を表示します。
- レッスン：未回答でも前後・目次へ移動できます。判定時に保存し、再読み込み後も回答と選択肢の表示順を維持します。
- 原問：本文・図はIPA PDFのページ画像です。部分練習と原問全体の答案は別々に保存します。

### 午後問題の学び方

**平成30年度 秋期 午後Ⅱ 問1は、原文読解型を先行導入しています。**
冒頭で12ページを提示せず、本文を5章・35の区切りに分けて表示します。
各区切りは「読む観点・用語メモ → 原文テキストと原図 → 理解チェック」の順です。
本文と章末の設問は原文をテキスト化し、スマートフォン幅で折り返します。図表は原画像を維持します。
文の途中では切らず、必要な前文は「原文の再掲」として重ねます。原画像との照合も開けます。
長い図6は条件別の三つのシーケンスと通信内容の例に分けています。
章末に、その章で読んだ内容に対応する原問へ解答します。
全14小問の答案・自己採点を確定すると、対応表でも原問を解答済みと数えます。
最後に全文を解き直す必要はありません。読解補助ありの解答で、全問正解とは区別します。
未回答でも前後・章の目次へ移動でき、移動だけで読解済みや解答済みにはなりません。
読解位置・理解チェックの判定・選択肢順・章ごとの答案はブラウザに保存します。
従来の79ステップは設問ごとの補助練習として残し、既存の記録も保持します。

以下は、ほかの49問の段階学習です。

1. 最初に原問・原図を眺めます。この時点では読解・解答を求めません。
2. その問題に必要な用語と仕組みを、短い説明と図で確認します。
3. 小さな条件から判断し、誤答との違い・判断の理由を確かめます。
4. 穴埋め・並べ替えで答案を組み立て、条件変更や原文の抜粋で理解を試します。
5. 最後に原問全体へ解答します。苦手な設問から、対応する練習節へ戻れます。

段階学習は選択・穴埋め・並べ替えだけで操作でき、文字入力は最後の原問で行います。
並べ替えはドラッグのほか上下ボタンにも対応します。長文の読み直しや実機コマンドの実行を必須にしません。
共通基礎章を連結しただけのコースではなく、大問ごとの専用JSONで学習内容を管理します。

「実施」は移動先の位置ではなく、回答・確認を記録したステップ数です。
練習を終えることと原問全体に解答することは別に数えます。
原問の解答済みには、全小問への答案入力と自己採点の確定が必要です。
自己採点は公式の配点・得点率ではありません。部分正解は正解数に含めません。
共通基礎教材を複数の過去問コースで使う場合、練習記録はコースごとに独立します。

## 記録の保存

保存先はブラウザの `localStorage`（`netsteps-v3`）です。ログイン・クラウド同期はありません。

- 設定からJSONを書き出し／読み込みできます。読み込み時は置換の確認を行います。
- 旧 `netsteps-v2` は削除しません。教材IDとステップIDで引き継ぎます。
- 旧数値インデックスの記録は、教材の大きさが一致するときだけ対応付けます。
- 安全に対応付けられない記録は `engine.legacyRecords` に保管し、進捗には加えません。
- 壊れた保存データは自動で上書きしません。設定から元データを救出できます。
- localhostと公開URLは保存領域が異なります。移行前に書き出し、公開URLで読み込んでください。

## GitHub Pagesで公開する

公開先はGitHub Pagesです。`main` へのpush後、以下のワークフローが検証・公開を行います。

1. GitHubリポジトリを用意し、`main` ブランチを作成します。
2. 公開対象を確認し、コードと生成済み画像をpushします。個人の学習記録は含めません。
3. Settings → Pages → Build and deployment → Sourceを **GitHub Actions** にします。
4. Actionsの **Deploy to GitHub Pages** を実行します（mainへのpushでも実行）。
5. 発行URLで画像表示・回答保存・再読み込み・バックアップ読み込みを確認します。

`.github/workflows/deploy-pages.yml` は型検査・教材検証・ビルド後に `dist` を公開します。
ベースパスには `actions/configure-pages` の出力を使用します。
手動ビルドは `VITE_BASE_PATH=/repository-name/ npm run build` でも指定できます。
そのビルドをプレビューするときも、同じ `VITE_BASE_PATH` を指定してください。
ハッシュルーティングなのでレッスンURLの再読み込みにサーバのrewriteは不要です。

参考：[GitHub公式のカスタムワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
／[公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

### 公開前の確認

公開前レビューの結果と制約は [SECURITY_REVIEW.md](docs/SECURITY_REVIEW.md) に記録しています。

- `public` 全体が配信されます（現状約158MB）。原問・解答例も閲覧できます。
- 教材・解答はビルドに含まれます。解答を秘匿する試験システムではありません。
- IPA原典の出典表示を維持してください。外部書籍のサンプルを本文として転載しないでください。
- 個人バックアップ・秘密情報・作業ログをリポジトリへ入れないでください。
- 認証や同期が必要なら、別途ユーザー管理と保存APIを設計します。

## コンテンツと原典データ

| ファイル | 役割 |
| --- | --- |
| `src/content/courses/*.json` | 基礎章と個別過去問コース |
| `src/content/workshops/*.json` | 大問別の段階学習。各節に対応小問・説明・タップ問題・原図抜粋を定義 |
| `src/content/readings/*.json` | 原文読解型。本文順の切り出し、理解チェック、章末の対応小問を定義 |
| `src/content/reading-transcripts/*.json` | 原文テキスト・再掲文脈・原図の範囲。読解本文と章末の全小問を管理 |
| `src/content/learning-paths.json` | 旧39問の関連テーマ・導入・接続情報。新教材がある場合は専用の段階学習を優先 |
| `src/content/themes.json` | 章と主テーマ |
| `src/content/exam-plans.json` | 公式PDFの大問別ページ境界 |
| `src/content/originals.json` | 50問の原典、解答欄、画像、抜粋領域 |
| `data/ipa/` | 再生成用の公式PDF（公開リポジトリには含めません） |
| `data/original-index/` | 再生成用の索引（公開リポジトリには含めません） |
| `public/ipa/originals/` | 公式PDFから書き出したページ画像 |

OCRは抜粋の位置指定にだけ使用し、問題本文の代わりには表示しません。
小問を安全に切り出せない場合は設問単位の領域を表示します。
解答例の抽出テキストは表組みが崩れる場合があるため、原画像も参照できます。

通常のビルドは生成済みJSON・画像を使用するため、PDF関連ツールは不要です。
索引再生成はmacOSのPDFKit/Vision、カタログ再生成は `pdftotext` が必要です。

```sh
swiftc scripts/index_originals.swift -o /tmp/netsteps-index-originals
# 索引生成の引数は scripts/index_originals.swift を参照
node scripts/build_original_catalog.mjs
npm run validate
```

午後教材の執筆は `docs/WORKSHOP_AUTHORING.md`、基礎章は `docs/COURSE_AUTHORING.md`、文体は `docs/WRITING_STYLE.md` を参照してください。
`node scripts/validate_workshops.mjs --complete` は全50問への教材割当てを検査します。
`node scripts/validate_readings.mjs` は読解教材の原画像・順序・全小問の重複なしの割当てを検査します。
検証は構造・参照・必要な問題形式を確認するもので、技術的正確性や学習効果を保証するものではありません。
内部の作業記録は公開リポジトリには含めません。現行仕様は本READMEを参照してください。

## 出典と加工表示

- アプリの「出典・利用について」に利用方針・参考資料一覧・保存方法を表示します。
- 各午前問題にIPAの試験名・年度・区分・問番号、選択肢順の変更、図表の再作成を表示します。
- 午後の段階練習は「過去問を基に作成」、原文は「IPA原文・原図」と区別します。
- 原文テキストの抜粋・改行調整、原画像の切り出し、解説の独自作成を明記します。
- 本サイトはIPAの公式・監修教材ではありません。試験問題の権利はIPAに帰属します。
- 出典レコードの検証は `npm run validate` に含みます。原文の正確性の全数照合を代替するものではありません。
