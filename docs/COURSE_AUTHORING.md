# コースJSON 執筆ガイド

## Web版の原問・進捗に関する補足

- 原問の本文・図は `originals.json` が参照するIPA PDF画像を表示する。模擬事例を原問と表示しない。
- 設問専用の段階解説がある11問と、共通基礎＋原問分割の39問を区別する。後者の各設問の根拠説明は未整備。
- `learning-paths.json` で基礎テーマと原問の接続を管理する。表示コードに教材本文を書かない。
- ステップIDは保存済み回答のキーなので、既存IDを別内容に再利用しない。
- 原問の自己採点と練習の判定は別記録。最後のステップを通過しただけで原問を完了扱いしない。
- 設問文を「〜は何か。」に限定しない。比較・計算・状況判断・手順など目的に合った問い方を使う。
- 現行例は `ch11-routing.json`、個別過去問の設計例は `r7q1.json`。旧 `ospf-basics.json` への参照は歴史的なもの。


> **文章の書き方は [docs/WRITING_STYLE.md](WRITING_STYLE.md) が最優先。必ず先に読むこと。**
> バリデータが禁止表現と一文の長さを機械検査する(0 errors 必須)。
> テーマは市販ワークブックに合わせた20章構成(`src/content/themes.json`)。

NetSteps のコースは `src/content/courses/<id>.json` に1ファイル1コースで置く。
アプリは JSON を自動で読み込む(コード変更不要)。**必ず最後に
`node scripts/validate_courses.mjs src/content/courses/<id>.json` を実行し、0 errors にすること。**

良い実例: `src/content/courses/ospf-basics.json`(52ステップ)。**書き始める前に必ず読むこと。**
トーン・分量・解説の深さ・選択肢の作り方はこのファイルに合わせる。

## トップレベル

```json
{
  "id": "dns-basics",            // ファイル名と一致
  "theme": "dns",                // src/content/themes.json のテーマID
  "chip": "基礎コース",
  "kind": "basics",
  "order": 40,                    // テーマorder×10 で指定される
  "title": "DNS・DHCP・ARP総合 — 名前解決をゼロから",
  "desc": "ホームのカードに出る2文程度の説明。",
  "steps": [ ... ]
}
```

## ステップ共通フィールド

`id`(コース内一意, 例 "d1")・`scaffold`(5→1で漸減)・`format`(表示ラベル: 読む/選択/穴埋め/並べ替え/計算/午前Ⅱ)・`type`・`theme`(小さなチップ表示, 例 "dns")。
任意: `fig`(図)・`source`(過去問出典)・`intro`(設問前の一言)。

## ステップ種別

### info(読む)
```json
{ "id": "d1", "scaffold": 5, "format": "読む", "type": "info", "theme": "dns",
  "title": "見出し", "body": "段落1\n\n段落2(\\n\\nで段落分け)",
  "dialog": [{ "q": "学習者の素朴な疑問。1文。", "a": "回答。結論→理由の順に2〜4文。" }] }
```
`dialog` は手本の吹き出しに相当する。**1コースに2〜4個**、つまずきやすい箇所の info に置く。

### quiz(選択) — 主力。1問1概念
```json
{ "id": "d2", "scaffold": 5, "format": "選択", "type": "quiz", "theme": "dns",
  "title": "設問文?",
  "intro": "(任意)導入の一言",
  "choices": [
    { "text": "正解", "ok": true, "explain": "なぜ正しいか+次への接続。2-3文" },
    { "text": "誤答A", "explain": "なぜ誤りか。関連する正しい知識も1つ添える" },
    { "text": "誤答B", "explain": "同上" }
  ] }
```
- 選択肢は3つ(午前Ⅱ実物のみ4つ)。**表示時に自動シャッフルされる**ので並び順は気にしない
- **誤答は実在する用語・もっともらしい技術的誤解にする。** 冗談や明らかに非技術的な選択肢は禁止
- 全選択肢に explain 必須

### blank(穴埋め)
```json
{ "id": "d9", "scaffold": 4, "format": "穴埋め", "type": "blank", "theme": "dns",
  "title": "ここまでの整理: 空欄を埋めよ",
  "template": "…{a}…{b}…",
  "blanks": [
    { "key": "a", "label": "a",
      "choices": [{ "text": "正解", "ok": true }, { "text": "誤答" }, { "text": "誤答" }],
      "why": "a: 解説" } ] }
```

### parsons(並べ替え)
```json
{ "id": "d20", "scaffold": 4, "format": "並べ替え", "type": "parsons", "theme": "dns",
  "title": "…を正しい順に並べ替えよ", "lead": "行をドラッグ…",
  "lines": [{ "code": "手順1" }, { "code": "手順2" }, ...],   // 正解順で書く
  "shuffled": [3,0,4,1,5,2],                                   // 初期表示順(正解順と別)
  "okOrders": [[0,1,2,3,4,5]],
  "okExplain": "…", "ngExplain": "…" }
```

### calc(計算)
```json
{ "id": "d24", "scaffold": 3, "format": "計算", "type": "calc", "theme": "dns",
  "title": "…", "given": ["前提1", "前提2"], "question": "…はいくつか。",
  "unit": "", "answer": 10, "placeholder": "数値を入力",
  "success": "正解時解説", "fail": "誤答時ヒント" }
```

### 図(fig) — 至る所に置く。構成図は必ず topo を使う
文字列でレジストリID、またはJSONで汎用図を定義。quiz/info/blank/parsons/calcに付けられる。
infoで配列にすると「段落1→図1→段落2→図2…」と交互に挿入される。
**旧レジストリID(文字列指定の図)は使わない**。すべてJSONで定義する。
- **汎用図:**
```json
"fig": { "kind": "flow", "steps": [ { "t": "① 問合せ", "d": "説明(任意)" }, { "t": "② 応答" } ], "caption": "任意" }
"fig": { "kind": "net", "height": 140,
  "nodes": [ { "id": "pc", "x": 50, "y": 40, "label": "PC", "sub": "任意", "active": true } ],
  "links": [ { "from": "pc", "to": "sv", "label": "任意", "arrow": true, "dash": false, "double": false } ],
  "caption": "任意" }
"fig": { "kind": "table", "head": ["", "A", "B"], "rows": [["行1", "…", "…"]], "caption": "任意" }
```
**構成図・パケット構造・実機出力は、以下の専用の図を使う**(net の素朴な箱より読みやすい)。

```json
// 構成図: 機器アイコン付き。ネットワーク構成は必ずこれを使う(netは使わない)
"fig": { "kind": "topo", "height": 200,
  "zones": [ { "x": 6, "y": 100, "w": 150, "h": 96, "label": "本社LAN", "dashed": false } ],
  "nodes": [ { "id": "pc", "x": 36, "y": 130, "label": "PC", "sub": "任意", "icon": "pc", "hi": false } ],
  "links": [ { "from": "pc", "to": "sw", "label": "任意", "dash": false, "double": false } ],
  "caption": "任意" }
// icon: pc / server / router / l2sw / l3sw / fw / cloud / internet / ap / phone
// 座標: viewBox 0 0 340 height。x は 24〜316、y は 16〜(height-34)。ノード間は縦横とも45以上あける

// カプセル化: 上の層のデータが下の層のヘッダに包まれる入れ子
"fig": { "kind": "encap", "layers": [
  { "label": "アプリケーション", "parts": [ { "t": "HTTPリクエスト", "w": 100, "role": "data" } ] },
  { "label": "トランスポート", "parts": [ { "t": "TCPヘッダ 20B", "w": 22, "role": "header" }, { "t": "データ", "w": 100, "role": "data" } ] }
], "caption": "任意" }   // role: header | data | trailer、w は相対幅

// ヘッダ構造: 1行=32ビット。各行の bits 合計は必ず 32(unitを変えたらその値)
"fig": { "kind": "header", "unit": 32, "rows": [
  { "fields": [ { "t": "バージョン", "bits": 4 }, { "t": "IHL", "bits": 4 }, { "t": "TOS", "bits": 8 }, { "t": "全長", "bits": 16, "hi": true } ] }
], "caption": "任意" }   // hi: true で強調(午後で問われるフィールドだけ)

// 数値の分解: 「何バイトか」を導出で示す
"fig": { "kind": "bits", "sep": ".",
  "cells": [ { "top": "255", "steps": ["8ビット", "1バイト"] } ],
  "total": "合計 4バイト", "note": "任意", "caption": "任意" }

// 実機の出力: 該当行を赤枠でハイライト
"fig": { "kind": "console", "lines": ["C:\\>ipconfig", "..."], "highlight": [5], "caption": "任意" }
```

**基礎コースには最低8枚の図を置くこと**。うち構成図(topo)を1枚以上、
パケット/ヘッダ構造を扱う章は encap か header を1枚以上、
実機で確かめられる章(ARP・DHCP・DNS・運用など)は console を1枚以上。

### 午前Ⅱ実物(過去問) — 本試験の問題をそのまま
```json
{ "id": "d18", "scaffold": 4, "format": "午前Ⅱ", "type": "quiz", "theme": "腕試し",
  "title": "問題文をそのまま。",
  "intro": "(任意)何が問われるかの一言。出典はintroに書かない",
  "source": { "label": "ネットワークスペシャリスト試験 令和5年 春期 午前Ⅱ 問3(IPA)",
              "url": "https://www.nw-siken.com/kakomon/05_haru/am2_3.html" },
  "choices": [ 4つ、原文どおり。正解にok:true ] }
```
**厳守**: 午前Ⅱ実物は、nw-siken.com(またはap-siken.com)の該当ページを実際に取得して、
問題文・選択肢・正解を確認できたものだけを収録する。確認できなければ収録しない
(代わりにオリジナルの定番問題を作る)。source.url には確認に使ったページを入れる。
解説(explain)は自分の言葉で書く(サイトの解説文の転載禁止)。
**最後にまとめて出さず、その内容を学んだ章の直後に配置する。**

## 章の構成テンプレート

1章 = 1コース。`id` は `ch{2桁}-{テーマID}`(例 `ch04-dhcp`)、`order` は 章番号×10。

1. **冒頭 info**: 「本章は、〇〇がテーマです。」で始め、扱う範囲を3〜4文で示す
2. **「そもそも」節(必須)**: 基礎の基礎から始める。**そのテーマの用語を1つも知らない読者を想定する**
   - 「〇〇とは何か」を、身近な言い方で1つ定義する(例: IPアドレスはネットワーク上の住所)
   - 「なぜ必要か」を、それが無いと何が困るかで示す
   - 「どこに出てくるか」を、実機の出力や構成図で見せる(console図・topo図)
   - この節だけで info 1〜2 + quiz 2〜4。**いきなり仕組みの詳細に入らない**
3. **本編**: 5〜8節。各節 = info 1 + quiz 2〜5。合間に blank / parsons / calc を挟む
4. **午前Ⅱ実物**: 学んだ直後に配置(最後にまとめない)
5. **末尾 info**: 「まとめ」。図を並べ、節ごとの要点を \n\n 区切りで短く振り返る

### 土台(第0章)との接続

第0章「ネットワークの土台」で、レイヤ・カプセル化・フレーム/パケット/セグメント・
機器とレイヤの対応を扱う。各章は、自分のテーマが**どの層の話か**を「そもそも」節で1文示すこと。
例: 「ARPは、IPアドレスからMACアドレスを引く仕組みです。第0章でいうと、
ネットワーク層とデータリンク層の境目で働きます。」

## 過去問コース(kind: "exam")の作り方

本試験の午後Ⅰ・午後Ⅱ1問を題材に、そこへ向けて逆算した演習を作る。手本は
`src/content/courses/r7q1.json`(令和7年 午後Ⅰ問1)。**書き始める前に必ず読むこと。**

### 過去問の扱い

IPAは、公表済みの試験問題について**許諾も使用料も不要**で使用を認めている
(ダウンロードでの利用も可)。条件は**出典の明記**で、IPA指定の書式は
「出典：令和7年度 春期 ネットワークスペシャリスト試験 午後Ⅰ 問1」。
改変した場合はその旨も明記する。著作権はIPAが保持している。
→ [IPA 過去問題](https://www.ipa.go.jp/shiken/mondai-kaiotu/index.html)

このアプリでは、次の2つを組み合わせる。

1. **本物の過去問**は、公式問題冊子のページ画像をそのまま表示する(`exam.official`)。
   `node scripts/attach_official.mjs <courseId> <examId> <pm1|pm2> <問> <開始p> <終了p> "<出典ラベル>"`
   でページを書き出してJSONに紐付ける。ページ範囲は
   `python scripts/page_index.py <PDF> out.png` で各ページ上端を一覧化して判別する
2. **練習用の事例**は、設問構造に 1対1 対応する短いオリジナルを書き起こす(`exam.body`)。
   市販ワークブックと同じ考え方で、長い本文を短く組み直して設問数を確保する。
   会社名・機器名・数値・構成は自分で作り、`exam.note` に出典と
   「事例文を新規に書き起こしたオリジナルの模擬問題」である旨を明記する

`showOfficial: true` を付けたステップで本物のページを表示できる。
完了画面には `exam.official` があれば自動で本物が出る。

### 素材の読み方

- `data/db/nw-db.json` に、全50問の**出題趣旨と公式解答例の全文**がテキストで入っている。
  ここから設問番号・配点構造・正解の要点が正確に読める(最優先で使う)
- 問題冊子PDF(`data/ipa/<試験ID>/<試験ID>_nw_pm1_qs.pdf` など)は画像なので、
  Read ツールに `pages` を指定してページ画像として読む(事例の設定と図の確認用)
- 採点講評PDF(`_cmnt.pdf`)には受験者の誤答傾向が書かれている。解説に活かせる

### JSONの形

```json
{
  "id": "r6pm1q2", "theme": "wan", "chip": "過去問コース", "kind": "exam", "order": 131,
  "title": "R6 午後Ⅰ 問2 SD-WANの導入",
  "desc": "(2文程度)",
  "done": { "tag": "+ solved · 設問1(1)〜設問3 完答", "title": "…", "sub": "…",
            "showCounter": true, "pdfHref": "/ipa/2024r06h_nw_pm1_qs.pdf" },
  "exam": {
    "label": "goal · 模擬問題(午後Ⅰ形式)",
    "title": "問2 B社のWAN更改に関する次の記述を読んで、設問1〜3に答えよ。",
    "body": [
      [ { "t": "B社は…" }, { "blank": "a" }, { "t": "…である。" },
        { "u": "下線部の文", "mark": "①" } ]
    ],
    "procTitle": "表 移行手順(任意)",
    "procedure": [ { "no": "1-1", "segs": [ { "u": "…", "mark": "⑤" } ] } ],
    "figure": { "kind": "topo", "…": "構成図をJSONで描く(公式図は使わない)" },
    "questions": [ "設問1 …について答えよ。", "　(1) 本文中の( a )に入れる字句を答えよ。" ],
    "note": "※ 本問は、IPA 令和6年度 春期 午後Ⅰ問2 の設問構造を基に、事例文を新規に書き起こしたオリジナルの模擬問題です。"
  },
  "steps": [ … ]
}
```

- `body` のセグメント: `{t}` 地の文 / `{blank}` 空欄 / `{u, mark}` 下線部
- **空欄と下線には、必ず対応する設問を `questions` に書く**(バリデータが照合する)
- `figure` は topo などのJSON図で描く(公式図の切り出しは使わない)

### ステップの流れ(難易度カーブ)

r7q1 と同じ順にする。**いきなり事例文を読ませない**。

1. `type: "goal"` — 事例を眺めるだけ。自己診断(さっぱり/設問1くらいは/解けそう)
2. この問題を解くのに必要な**基礎の復習**(該当章の内容を数問)。事例は出さない
3. **事例へ半歩ずつ** — `excerpt` で事例文から1〜2文だけ切り出して問う。全文は読ませない
4. 帰還 — `showExam: true` の info で初めて全文を通しで見せる
5. **実際の設問を本番と同じ順で解く** — 各ステップに `goalTag`(例 "設問1(1)")を付け、
   `excerpt` で該当箇所を添える。`showCase: true` で全文も参照できるようにする
6. 最後は `type: "write"` の `final: true`。公式解答例に沿った `kijutsu.model` と
   キーワード採点の `rubric` を置く

28〜36ステップ。図は6枚以上。`goalTag` は実際の設問番号に 1対1 で対応させる。

## 設計ルール(必読)

1. **難易度カーブ**: 知らない単語が出ない順に積み上げる。前半は前提ゼロ、
   scaffold 5→1 へ漸減。いきなり難しくしない
2. **用語**: IPA試験・一般IT用語のみ。造語禁止。比喩は「〜のイメージ」と補足位置に
3. **略語は初出時にフルスペル**: 例「DNS(Domain Name System)」。用語自体も初出時に定義
4. **根本を解説**: 「試験に出る」で終わらせず、なぜそうなるか(仕組み・歴史的理由)まで。
   ネスペ合格の手前に「エンジニアとしてテーマを理解できる」を置く
5. **1問1概念**。誤答選択肢の explain にも学びを入れる
6. **伏線**: 後の章や過去問で使う言い回しは「この言い回しは午後でそのまま出ます」等と接続する
7. **分量**: 28〜40ステップ。章構成(5〜8章)で、各章 = info 1 + quiz 2〜5。
   章の合間に blank/parsons/calc で形式を変える。最終ステップは「全体地図」info
   (図+章ごとの振り返りを \n\n 区切りで長めに)
8. **Webで裏取り**: 解説を書く前にテーマの初心者向け記事を検索して読み、
   典型的な説明・つまずきポイントを反映する
