# 文章スタイルガイド(必読・機械検査あり)

手本は市販のネスペ「ワークブック」(左門式)。**簡潔・端的・実務的**。
装飾や煽りを削り、事実と理由だけを短い文で積む。

`node scripts/validate_courses.mjs` が禁止表現と一文の長さを機械検査する。0 errors が必須。

## 1. 文の長さ

- **解説文は1文40字前後、最大60字**。長い文は必ず切る
- 1つの段落は3〜5文
- ダッシュ(——)は原則使わない。使うなら1コース1回まで

```
NG: 分かれ道(ネットワークの境界)で行き先を判断するのがルータです。では、ルータは行き先を
    どうやって知るのか? ルータ同士で情報を交換し合う仕組み=ルーティングプロトコルが今日の
    主役で、その代表がOSPFです。
OK: ネットワークの境界で行き先を判断するのがルータです。では、ルータはその行き先を
    どうやって知るのでしょうか。ルータ同士で経路情報を交換する仕組みが、ルーティング
    プロトコルです。代表的なものがOSPFです。
```

## 2. 文体

- 解説・explain: **敬体(です・ます)**
- 問題文(title): **端的に**。無駄な修飾や煽りを付けない
  - 手本: 「DHCPサーバに設定する主な情報は何か。」「なぜ、上記のようにまとまった単位でデータを送るのか。」
  - **形は限定しない**。「〜は何か。」「なぜ〜か。」「〜を答えよ。」「〜はどれか。」「〜を述べよ。」
    「〜した場合、何が起きるか。」など、問う内容に合った形を選ぶ。問題の幅を狭めないこと
  - 本試験から引用する問題文は**原文のまま**(疑問符や記号もそのまま)
- 言い切る。「〜と覚えてください」「〜と考えて構いません」は避け、「〜です」と書く

## 3. 禁止表現(バリデータが検出)

| 種別 | 例 |
|---|---|
| 煽り・情緒 | もったいない、大したもの、怖くありません、悔しい、一瞬、鵜呑み、ド真ん中、爆発 |
| 芝居がかった比喩 | 主役、正体、急所、肝、ミソ、通奏低音、背骨、学級委員、名刺、噂話、バケツリレー、洪水 |
| 顔文字・記号 | (笑)、!!、!? |
| 過度な強調 | 必ず落とします、絶対に、断言 |
| 冗長な前置き | 〜というわけです、〜なのです(多用) |

比喩は**1コースにつき2回まで**、かつ「〜のようなものです」「〜のイメージです」の形で
1文に収めて補足位置に置く。用語そのものを比喩で置き換えない(造語禁止)。

## 4. 解説の型(explain)

**事実 → 理由 → 試験での出方**の順に、各1〜2文。

```
OK: LSAは「私にはこの回線がつながっている」という自己申告です。全員分を集めると
    LSDBになります。午後の事例文では「LSAの交換が完了してから」という形で登場します。
```

誤答のexplainも同じ型で書く。「なぜ違うのか」+「その用語の正しい説明」。

## 5. 対話(dialog)

学習者の素朴な疑問と、その回答を置ける。手本のキャラクター吹き出しに相当する。
**info ステップに1〜2個**、章の途中でつまずきやすい点に置く。

```json
"dialog": [{ "q": "ノートに書いたほうがいいですか。",
             "a": "書くことは必須ではありません。ただ、読むだけだと上っ面の理解で
                   止まりがちです。本試験で書こうとして書けない、ということが起きます。" }]
```

- q は学習者の素朴な質問。1文
- a は2〜4文。まず結論、次に理由

## 6. 実務の視点

各章に1〜2箇所、「実務ではこうする」「現場ではここでつまずく」を入れる。
根拠のない体験談は書かない。一般に知られた運用上の事実だけを書く。

## 7. 章の冒頭(section 1 の最初の info)

手本と同じ構成にする。3〜4文で足りる。

```
本章は、DHCPがテーマです。DHCPを中心に、DHCPリレーエージェントやDHCPスヌーピング
などを扱います。
まずはステップ1で、短答式問題にチャレンジしてください。頭の中だけで答えるのではなく、
言葉にしてから選択肢を見ると力がつきます。
```
